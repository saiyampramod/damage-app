# Damage (iOS and Android app)

Damage splits group bills item by item and settles them over UPI. Snap a receipt, everyone taps what they had, the app works out the fewest payments. This folder is the native app, built with Expo. See `AGENTS.md` for Expo-specific rules (always read the versioned Expo docs; install packages with `npx expo install`).

## Where it lives

`C:\dev\damage`. Keep it out of `C:\Users\saiya\apps` and `packages`: those belong to the loqa monorepo, whose `package.json` in the user folder claims them as npm workspaces, so installs there land in loqa's `node_modules`. If `npm prefix` ever prints anything other than this folder, stop and check.

## Run it

```bash
npm install
npx expo start        # scan the QR code with Expo Go on your phone
npx tsc --noEmit      # typecheck before calling anything done
```

## Stack

- Expo SDK 57, React Native 0.86, TypeScript, new architecture.
- Expo Router. Every file in `src/app/` is a screen. Non-route code lives outside `src/app/`.
- `react-native-svg` for the tear tile, stickers, icons and dashed lines.
- **No dotted paper anywhere** (the founder's call, 24 Oct): `DottedBackground` now paints plain white. Every screen still mounts it, so a texture can come back in one place.
- Hard shadows use the `boxShadow` style prop (`'4px 4px 0px #000'`), not `shadow*`/`elevation`.
- `expo-clipboard` for Copy on your friend code (Profile, Friends). Invite links have no Copy: Share link is the one way to send them.
- `expo-camera` for the viewfinder, `expo-image-picker` for Upload. Both work in Expo Go on a real phone (no camera in simulators). Only one camera can run at a time, so `/scan` drops it when another screen is on top.

## Design rules

- **Colours and fonts are not final.** Every component reads from `src/theme/tokens.ts`. Never hard-code a hex value or a font name anywhere else. To change a font, load it in `src/app/_layout.tsx` and point the role in `fonts`.
- Current look: lime and white, with slate ink. The "black" is Slate `#1B1F27`, a soft blue-black (the founder's pick, 22 Oct, to be easier on the eye; it was pure `#000000`), with `#414754` for softer text. The page is pure white `#FFFFFF`, the same as cards, tags and the nav bar (one white everywhere, the founder's call, 24 Oct; it was a cool white `#F5F6F8` behind dots). Outlines and hard shadows use the same slate. Tried alongside it: charcoal `#1A1A1A`, graphite `#2B2B2B`, warm ink on paper. Thick black outlines, hard offset shadows, slight tilts, a plain white page (no dots). People are flat round avatars in their own colour with their initial (`avatarColors` in tokens; you are lime); overlapping avatars get a white ring. Home's two "biggest each way" people are the same avatars, big, with the amount on a black pill. No die-cut stickers anywhere now.
- **Bill colours (the founder's scheme, 14 Oct):** lime = a bill waiting on you (tag, who paid, close), black = money coming back to you, white = you owe, faded = settled. Same on the price tags, the mini tags on rows (`MiniTone`) and the Quick fan. The tokens are `needsFill` (lime), `owedFill` (black), `oweFill` (white) with their `on*` text colours. A black tag's number is bright green (`colors.inOnInk`, the founder asked for it on black), a lime tag's black, a white tag's −₹ red. Bill rows and a group's bill cards show money coming back in black. Only the **numbers** take a colour otherwise (decided by the founder; don't tint tags or cards):
  - coming to you: green with a + (`colors.inText`), only in people places (People rows, a group's pass, a person's page). Never on a bill.
  - you owe: red with a − (`colors.outText`)
  Only at the **key places**: People rows (people and groups), a group's pass, the number on a price tag, and the big number on a person's page. Everywhere else (Home's people pills, which stay white on black, the Home receipt, bill and group pages, payment cards, settle lists) amounts stay black, with the coloured "you owe" / "you get back" words where they were. Use `components/money/Signed` (`Signed`, `signed`, `wayColor`, `wayWords`) for the coloured ones. The words are always there too, so colour is never the only signal. `inWash` / `outWash` exist in tokens but are not used: pale green or red cards were tried and rejected.
- Show design changes (screenshots or the artifact) and get the founder's OK before copying them to C:\dev\damage.
- **React Compiler is on** (`app.json` → `experiments.reactCompiler`). Anything that reads the example data during render (it changes in place) needs `'use no memo'` at the top of the component, plus `useStore()`, or it won't redraw after a change.

## Product rules (from the wireframes)

- The app is for account holders. Guests only ever use the web link for one bill; they are never in the app, in circles or in anyone's totals.
- A bill goes: tag items → who paid → "What's the damage?" (locks it, works out the fewest payments) → settled. Settled bills delete themselves after 7 days unless kept. Statuses: `tag`, `paid`, `close`, `wait`, `settled`.
- A **group** adds several bills into one set of payments. Everyone in a group needs an account. Making one asks only for a name and (optionally) people: no kinds like trip or outing, no dates. It can be made with just you; others join with its QR or link.
- **Circles are gone** (decided by the founder): groups are the one way to keep people together. `Circle` and `circleId` still sit in `types.ts` / `mock.ts` as old example data; nothing reads them.
- Home totals are netted per person (like the Person screen). Bill tags show that bill's own amount.
- The app never moves money. Pay opens a UPI app with the ID and amount filled in, then asks "Did it go through?".

## The build preview artifact

A published artifact runs the real web build in a phone frame ("Damage Build Preview"). It is a snapshot: change the code here, then rebuild and republish it to the same artifact.

1. `npx expo export --platform web --output-dir <dist>` (in a Linux sandbox the Windows `node_modules` needs `lightningcss-linux-x64-gnu` on `NODE_PATH`; the first export is slow, rerun until it finishes).
2. `python scripts/web-preview/mkpreview.py <out-dir>` with the export at `~/webdist`: it inlines the bundle, fonts and images into one `index.html`, sizes the app to the frame and starts it at Home.
3. Publish that `index.html` to the existing artifact.
